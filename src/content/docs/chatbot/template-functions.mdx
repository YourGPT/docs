# YourGPT Templates Functions Guide

**YourGPT template functions** help you add dynamic content using default variables and helpers.



What Are Template Functions?
Template functions are special commands that help you make your chat responses dynamic and smart. Think of them as small tools that can:

Make decisions based on user information
Format text (like making text UPPERCASE or lowercase)
Handle dates and times
Combine information in useful ways

## Practical Use Cases

### 1. Technical Support Response
```handlebars
I see you're using {{VISITOR.browser}} on {{VISITOR.os}}. 
{{#if (eq VISITOR.browser "Safari")}}
For the best experience on Safari, please ensure you're using version 14 or higher.
{{else if (eq VISITOR.browser "Chrome")}}
Chrome provides optimal performance with our platform.
{{else}}
For the best experience, we recommend using Chrome or Safari.
{{/if}}
```
**Use Case:** This template is useful for technical support teams to provide browser-specific guidance to users, ensuring they have the best possible experience with the platform.

## Text Formatting Helpers

### Make Text UPPERCASE (NICE USECASE FOR TICKETS CONTACT ID)
```handlebars
Your ticket ID: {{uppercase (concat CONTACT.id "-" SESSION.id)}}
```

### Make Text lowercase
```handlebars
Email: {{lowercase CONTACT.email}}
```

### Combine Text (concat)
```handlebars
{{concat "Welcome back to " CONTACT.company ", " CONTACT.name "!"}}
```

## Working with Dates

### Show Current Date
```handlebars
Ticket created on: {{date format="MMMM Do, YYYY"}}
```

### Common Date Formats
- Short date: `{{date format="MM/DD/YYYY"}}` → 12/19/2024
- Long date: `{{date format="MMMM Do, YYYY"}}` → December 19th, 2024
- Day only: `{{date format="dddd"}}` → Thursday

## **Troubleshooting Guide**

### **1. Message Not Showing**  
✅ Check for closing tags like `{{/if}}`.  
✅ Verify that variable names are spelled correctly.  
✅ Use straight quotes (`"`) instead of curly quotes (`“`).  

❌ Don’t leave tags incomplete; it can break your template.  
❌ Don’t use curly quotes as they are incompatible.  

---

### **2. Variable Shows as Blank**  
✅ Ensure the variable exists in your data source.  
✅ Double-check for typos in variable names.  
✅ Verify that the case (uppercase/lowercase) matches your data definition.  

❌ Don’t assume all variables are available without confirming.  
❌ Don’t ignore typos—they are a common cause of errors.  

---

### **3. Conditions Not Working**  
✅ Use `eq` for comparisons, e.g., `{{#if (eq X Y)}}`.  
✅ Check that parentheses and syntax are correct.  
✅ Remove any extra spaces in condition statements.  

❌ Don’t overlook syntax errors; even small ones matter.  
❌ Don’t use spaces where they shouldn’t be in conditions.  

---

## **Best Practices**

### **Do's**  
✅ Start with simple templates and test changes step by step.  
✅ Use comments to clarify logic in your templates:  
   ```handlebars
   {{!-- Example: This section handles premium users --}}
   {{#if (eq SESSION.type "premium")}}
     Premium content here
   {{/if}}
   ```  
✅ Organize templates by grouping related content together.  
✅ Use clear, descriptive names for templates and variables.  
✅ Test thoroughly with different data sets to ensure accuracy.  

---

### **Don’ts**  
❌ Don’t add complexity to templates before testing the basics.  
❌ Don’t leave templates uncommented, especially for complex logic.  
❌ Don’t mix unrelated content into the same template—it makes debugging harder.  
❌ Don’t skip testing; it’s essential to catch potential issues early.
